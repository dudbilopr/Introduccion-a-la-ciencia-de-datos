Demo Day: convencer a un panel con datos que existen

Cada equipo presenta su proyecto integrador como si buscara inversión: un problema real, datos reales, un modelo evaluado con honestidad y una decisión que alguien podría tomar mañana. El público evalúa con esta misma rúbrica.

Qué se entrega

Un repositorio público en GitHub con:

  1. README.md con la pregunta de decisión, quién la toma y la Gran Idea en una oración.
  2. Ficha de datos: fuente, autor, licencia, fecha, número de filas, diccionario de columnas con unidades y lo que el dato no permite afirmar.
  3. Cuaderno reproducible: limpieza, análisis exploratorio, modelo (regresión, clasificación o agrupamiento), comparación con una línea base y validación honesta.
  4. Sección de ética: a quién se equivoca el modelo, a quién expone y quién responde (semana 15).
  5. Diapositivas del pitch y declaración de uso de IA.
Los datos existen. No se aceptan datos inventados ni conjuntos de Kaggle sin autor o artículo de origen. Si un personaje o supuesto es del caso, se declara. Las semanas 7 a 15 de este curso muestran cómo documentar un dataset real.

Formato del Demo Day

  1. Pitch (6 minutos): problema, datos, hallazgo con un número, modelo contra la línea base, decisión recomendada, límite.
  2. Demo en vivo (2 minutos): una celda del cuaderno corriendo, o una predicción para un caso nuevo.
  3. Panel (2 minutos): el panel (docente e invitados) y el público hacen preguntas. Al menos una pregunta será: "¿qué pasaría si sus datos estuvieran equivocados?".

Evaluación por pares

Cada estudiante evalúa a dos equipos con la rúbrica y deja dos frases: lo más convincente y la pregunta que no se respondió. La nota de pares es formativa: el docente la usa para la retroalimentación final, no la promedia.

Lista de verificación antes de presentar

  • Todo número de las diapositivas aparece en el cuaderno y coincide.
  • El modelo se compara con una línea base y se dice cuál.
  • Se revisaron filas duplicadas antes de partir los datos.
  • Ninguna variable del modelo es posterior al momento de decidir.
  • Asociación no se presenta como causa.
  • La declaración de uso de IA dice herramienta, para qué, prompt y qué se verificó.
